# 07 — 五条备用打法(创造性视角)

> 这份文档不解决谜题,它记录**五种"换姿势"的做法**,以及每种做法需要什么、能省什么、
> 第一步该做什么。五条按"从推理型到工程型"排列。
> 工具与硬结论见 `03-hard-deductions.md`,右下角那一轮见 `04-05-bottom-right-inference.md`。

## ① 不解题,解"场" —— 把距离场写成整数约束

### 想法
标题就是提示:It's a **Metric**, Too。d 场本身就是一个度量函数;而步长代价 = `min(s_x, s_y)` 意味着
**"穿过一个面积 s 的州,坡度就是 s"**。整块盘面因此是一张**以首都为源、每州一个坡度的距离场**,
题面给了 33 个采样点。

既然如此,就不该去枚举州(仓库估的 1.3×10¹²),而该去**解一个整数场**。

### 形式化
变量:
- `d(x)` ∈ ℤ≥0,121 个;
- `s(x)` ∈ ℤ≥1,121 个(所在州面积);
- 归属关系用"每格一个州标签 + 州标签的面积计数"表示(或用流变量)。

约束:
1. `d(x) ≥ 0`;`d(x) = 0 ⟺ x 是首都`(`03` R3);
2. `d(x) ≤ d(y) + w(x,y)` 对所有相邻 x,y(Lipschitz,R6);
3. **L1 紧邻律**:每个 `d(x) > 0` 的 x 至少有一个邻居 y 使 `d(x) − d(y) = w(x,y)`;
4. `w(x,y) = min(s(x), s(y))` —— min 需要线性化(引入 `w` 变量 + `w ≤ s(x)`, `w ≤ s(y)`, `w ≥ s(x) + s(y) − M`);
5. 每州面积 = 该州格数;各州面积之和 = 121;
6. **奇偶律**:某州若含 d=0 的格,则该州面积为奇;某州面积为偶则不含 d=0 的格;
7. 33 个已发布数直接钉死 33 个 `d` 变量。

### 为什么值得
- 搜索维度是 **121 个 d + 121 个 s**,不是 10¹² 个州;
- 形状约束(对称)变成"存在一个对称 σ"的判定,可以在后处理里再筛;
- 还能直接问"答案可能是多少"这类问题:目标函数是 `Σ_r (Σ_c s(r,c))²`,可以直接写进 MILP 求可行域。

### 第一步
先只写 1–3 + 7(即"距离场"部分,不含州结构),用 MILP/CSP 求**所有满足 33 个采样点且满足紧邻律的 d 场**。
看解出来的 d 场里 `(5,9)`、`(6,10)`、`(4,9)` 这些未发布格的 d 值有多少种可能——
**这比枚举州便宜得多,而且直接给出"还有多少自由度"。**

### 代价
需要写模型;`min` 的线性化会引入大量弱约束,可能需要大 M 技巧。

## ② 用"紧边当尺子"批量读面积

### 想法
仓库把 6 条相邻已发布数字的边记成**下界**(≥)。但只要再加上**紧邻律**的"唯一性"版本,
相当一部分边可以升级成**等号**,即"这一对里较小的那个州面积恰好等于落差"。

### 为什么紧邻律能升级
`d(x)=v` 的最短路第一步必然到达某个邻居 y 使 `d(y) = v − min(s(x), s(y))`(`03` T3)。
如果 x 的**已发布邻居里只有一个 d 更小**,而我们又知道其它未发布邻居的 d 有下界,
就可以比较出紧邻是谁 ⇒ 得出精确面积。

**已在本仓库里跑通的两例**(见 `03` D2、`04-05` §3):
- `(7,10)=13` 的紧邻是 `(6,10)`(前缀 48 卡死)⇒ `min(s(7,10), s(6,10)) = 12`;
- `(10,9)=61` 的前缀必须是 5 个 12 步 + 1 个 1 步 ⇒ 路径唯一到 3 条。

### 为什么值得
面积一旦定死,题目从"找形状"降维成"排格子":`12` 的州、面积已知 ⇒ 它的 d 锥完全确定,
剩下的只有"哪些格子在这个锥上"。

### 第一步
把 33 个已发布格按"已发布邻居中 d 更小的有几个"分类:
- 0 个 → 无信息;
- 1 个 → 候选紧边(需另证不是被某个未发布邻居抢走);
- ≥2 个 → 需要别的工具。

这个分类用手算就能做,一天的活。

### 代价
"唯一更小邻居 ⇒ 必紧"这一步**不是自动成立的**(5×5 官方例子里 `(3,1)=7` 的紧邻是未发布的 `(2,1)`,不是已发布的 `(3,2)=6`)。
⇒ 必须逐边**证明**紧邻是谁,不能默认。

## ③ 先锁首都,再长州 —— 最锋利的一把刀 ★

### 想法
仓库已经算出一个隐藏首都的**命中集**:
9 个已发布格需要附近有隐藏首都,最少还要 **4 个**隐藏首都,一共 120 个最小集合。
**这 4 个首都位置几乎被钉死了**,而首都位置一旦定下,州的对称就定下,州就只剩"选哪些轨道"一个自由度。

### 为什么这是数量级上的差别
|  | 状态空间 |
|---|---|
| 枚举州 | ≈ 1.3×10¹²(仓库估计) |
| 枚举 (首都位置 × 对称类型 × 轨道子集) | 4 个位置 × 每位 ≤6 种对称 × 每位 2^10 量级轨道选择 ≈ 10³–10⁴ |

⇒ **这不是"更聪明的枚举",是换了一个维度。**

### 首都位置 ⇒ 对称类型 ⇒ 州形状
一个州有首都 ⇒ 它有一个非平凡自对称 σ 且 σ 恰好固定首都一格(`03` R7 + D5)。
σ 只能是晶格对称(平移、反射、旋转、斜列),而**板角/板边的位置会把候选 σ 砍到只剩 1–3 个**:

| 首都位置 | 候选 σ | 后果 |
|---|---|---|
| 板角(如 `(0,0)`) | 主对角线转置(其它把格子推出板外) | 州 = 首都 + 转置对;**连通性立刻逼出关键格** |
| 板边(如 `(10,5)`) | 反对角线 / 竖线 / 横线 / 90° 旋转 | 各对应一个"带状/角状"族 |
| 内部(如 `(5,7)`) | 6 种以上 | 自由度大,放到最后 |

### 第一步
把命中集里那 120 个最小集逐一展开成 0-based 的 4 个坐标,
按"该坐标作为首都时,有多少种可行 σ"排序;
**先攻候选 σ 最少的那一个**(板角/板边),因为它一落定就砍掉一大片。
然后对每个 σ,手工枚举"州 = 首都 + 若干轨道",用 `03` 的 T1–T8 逐条体检。

### 代价
需要手工做 4 个首都位置 × 若干 σ 的轨道枚举;
但这是**可以并行交给子 agent 的活**(每个 (位置, σ) 一个分支),不像整盘枚举那样无法切分。

## ④ 先算答案需要的行剖面,别先找形状

### 想法
仓库的 `constraint_register` C 项已经指出:
**答案 = Σ_rows (row_sum)²,而 row_sum(r) = Σ_{c∈r} s(r,c)**。
⇒ 答案只取决于"每行分到哪些尺寸",**不取决于形状**。
同时 `Σ_r row_sum(r) = Σ_k s_k² = Q`,只取决于**尺寸多重集**。

所以求解目标可以重排成:
1. 先定**尺寸多重集**(决定 Q);
2. 再定**行剖面**(决定答案);
3. 最后才是形状(只起"筛掉非法剖面"的作用)。

### 为什么值得
- 行剖面只有 11 个整数,可能的剖面数远小于划分数;
- 剖面与形状**解耦** ⇒ 可以把"形状合法性"从搜索维度里彻底踢出去,变成事后校验;
- 尺寸多重集受守恒律、奇偶律、命中集、面积下界多重夹逼,可枚举空间小。

### 第一步
把已知尺寸地板列成不等式(1 / 8 / 12 / 16 / ≥4 / ≥6 / ≥2 / ≥16 …),
配合"奇面积州必含首都"和"至少 2 个单胞",
列出所有可能的尺寸多重集,算每个的 Q 与答案下界 `Q²/11`;
看哪个 Q 能对上 `04-05` 推出的州尺寸结构。

### 代价
尺寸多重集本身可能是几万个(`size_multiset_11x11.json` 的 loose 变体就到 27 万–41 万),
需要剪枝;但它们是**一维整数问题**,远比二维划分友好。

## ⑤ 一个两分钟能出结果的便宜实验:`(10,5)` 州的对称假设

### 想法
`(10,5)` 是**已发布的首都**,而且在板角附近 ⇒ 它的州只有很少几种可能的 σ:
反对角线反射 `r ↔ 10−c`、竖线 `c=5`、横线 `r=10`、绕 `(10,5)` 的 90°/180° 旋转。

**假设 H:** `(10,5)` 的州关于**反对角线**对称 `(r,c) ↔ (10−c, 10−r)`。
若 H 成立,则该州必须满足:
- 除 `(10,5)` 外,**反对角线上所有格都不属于该州**:`(9,1) (8,2) (7,3) (6,4) (5,5) (4,6) (3,7) (2,8) (1,9) (0,10)`;
- 每个 `(10,c)` 必与 `(10−c, 0)` 同州。

### 为什么这个实验便宜
- `(5,5)=10` **是已发布数字**。若 H 成立,`(5,5)` 必在另一个州(面积 ≥12 的奇州,含自己的首都)。
  ⇒ **用 `(5,5)` 一条数字就能证伪或坐实 H**。
- 同理 `(10,1)=26`、`(6,0)=11`、`(10,4)`、`(9,0)` 成对出现,可交叉验证。

### 其它候选 σ 的后果(备查)
| 假设 | 立刻排除的格 |
|---|---|
| 反对角线对称 | 反对角线上除 `(10,5)` 外的全部 10 格 |
| 竖线 `c=5` 对称 | 第 5 列除 `(10,5)` 外的全部(含 `(0,5)=11`、`(5,5)=10`) |
| 横线 `r=10` 对称 | 第 10 行除 `(10,5)` 外的全部(含 `(10,1)=26`、`(10,8)=77`、`(10,9)=61`) |
| 绕 `(10,5)` 90° 旋转 | (10,5) 之外要 4 元组轨道,州面积 ≡ 1 (mod 4) |

⇒ **四种假设各自排除一大片已发布格,互斥性很强 ⇒ 一测一个准。**

### 附带的好处
`(10,5)` 州一旦定形,它就给出 `(10,4)`、`(9,5)`、`(10,6)` 的 d 值
(离 `(10,5)` 一步 = 该州面积 s;两步 = 2s …),
这几个 d 值目前全是空白,而它们正是 16 州与 12 州之间的接缝处。

### 代价
几乎为零——四个假设各查 3 条已发布数字即可。

## 五条怎么排

| 顺序 | 打法 | 类型 | 产出 |
|---|---|---|---|
| 0 | ⑤ `(10,5)` 对称假设 | 推理 / 极便宜 | 2 分钟内可能坐实一个州的对称族 |
| 1 | ③ 先锁首都 | 推理 + 可并行 | 把 10¹² 砍到 10³ 量级的主攻框架 |
| 2 | ② 紧边当尺子 | 推理 | 更多精确面积 |
| 3 | ① 解场(MILP) | 工程 | 自由度的量化答案 + 可能直接出解 |
| 4 | ④ 行剖面优先 | 工程 | 答案候选集,形状只做校验 |

**并行的现实建议:** ③ 的每个 `(首都位置, σ)` 分支可以交给独立的子 agent 各自跑一遍,
每个 agent 只需要"规则 + 33 个数 + 一条分支"三样东西,不需要共享上下文。
这是本仓库目前架构下最容易被忽略的加速点——
现在的 `src/solver.py` 是整盘一次性搜,而**形状问题的天然可切分性被浪费了**。
