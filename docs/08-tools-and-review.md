## 1. 为什么要有自己的内核

`js-puzzle` 仓库的 `src/rules.py` 是"可执行规格",但本轮要**从零重写一遍**再拿它当**独立裁判**,
这样"我的推理对不对"和"仓库的实现对不对"是两件独立的事,不会互相污染。

`lr11/kernel.py` 按**官方原文**写:

| 官方原文 | 实现 |
|---|---|
| "A state is a connected group of squares **that is symmetric in some way**" | `is_legal_state` = 4-连通 **且** 至少有一个非平凡自对称。**没有对称的形状根本不是州** |
| "If **every nontrivial rotation or reflection of the plane** that takes a state to itself leaves exactly 1 of its squares fixed, then that square is its capitol" | `capitol_of`:对**整个对称群**量化,不是对某一个对称;只要有一个对称固定了 ≠1 格就没有首都;所有对称必须固定**同一格** |
| "the size of the state you are travelling in, or, if travelling between two states, **the lesser of the two states' sizes**" | `w(x,y) = min(s(x), s(y))`(同州时两项相同,一个式子覆盖两种情况) |
| "the lowest cost of travelling from the numbered square to any state capitol" | `cost_field`:Dijkstra,边权 `min(s_x,s_y)` |
| "the sum of the squares of these row sums" | `row_sums` + `answer` |

### 验证(`lr11/selftest.py`,全绿)

| 检查 | 结果 |
|---|---|
| 官方 5×5 例子 | 州面积 7/4/3/11、首都 (2,1)/(2,3)/(4,4)、**10 个已发布数全中**、行剖面 [37,29,31,43,55]、答案 **8,045** ✅ |
| 仓库 4×4 反例 | 两个划分答案 **304 / 112**、d 场一致 ✅ |
| **差分测试 vs 仓库 `src/rules.py`** | 4000 个随机连通形状:对称群 / 首都 / 合法性**零分歧** ✅ |
| **差分测试(定向:对角对称形状)** | 额外 3000 个**构造出来带对角对称**的形状:零分歧 ✅ |

> 第二条差分测试是补上去的:随机团块几乎不会带对角对称,所以第一轮差分测试基本没覆盖 `refD1/refD2`
> 和半格点中心的 90° 旋转。补上之后仍然全绿 ⇒ 内核的对称几何是对的。

## 2. 两个工具

### 工具 ③ `grow_states` —— 轨道生长枚举器

**原理**:官方规则说州"关于某个旋转/反射对称",所以一个州**必然是某个 σ 的轨道之并**。
于是:枚举板上的全部 σ 实例 → 对每个 σ 求轨道划分 → 沿着"与已有格子相邻"的轨道逐个加,直到达到目标面积。

**为什么这么枚举**:州的空间是 10¹² 量级(仓库估计),但**固定住面积 + 锚点 + 对称性**之后,
右下角一个 12 州只剩 **几百个**候选。

**σ 实例清单**(覆盖 11×11 板上的全部晶格对称):
- `refV@b`、`refH@a`,a/b ∈ {0, 0.5, …, 10} —— 轴可以在两列之间;
- `rot180@(a,b)`,a/b ∈ {0, 0.5, …, 10};
- `rot90@(a,b)`、`rot270@(a,b)`,**中心可以是格点,也可以是半格点**(半格点中心的 4 重旋转也把格点映成格点);
- `refD1@k`(r−c=k)、`refD2@k`(r+c=k)。

### 工具 ② `check_partial` —— 部分划分的一致性判定

给定若干**完全指定**的州(以及未覆盖的自由格),输出三类**严格**结论:

| 输出 | 含义 | 严格性 |
|---|---|---|
| `contradicted` | 已发布值 v 与 **UB(x) < v** 冲突 | **严格**。UB = 到"已揭示首都"的**最便宜合法路径**的代价;自由格之间的边没有上界,故禁止使用,自由格与已知格之间的边按已知格面积计(min(k,s_free) ≤ k,这是上界)。故 d(x) ≤ UB(x) |
| `needs_hidden_capitol` | v 小于到最近**已揭示**首都的乐观距离 | **严格**,但方向是反的:d(x) 是到**所有**首都的最小值,未知首都可能更近 ⇒ **"这里必须存在一个未揭示的首都"**(命中集约束) |
| `structural_problems` | 指定的州不连通 / 没有对称 / 首都与已发布 0 冲突 | **严格** |

> ⚠️ **我在开发中踩过的坑,写在这里以免重犯**:我最初把"到已揭示首都的乐观距离"当成了 d 的**下界**,
> 并用它判"矛盾"。**这是错的**——d 取遍所有首都,未知首都可以更近。那条规则会误杀**每一个**真解。
> 修正后:只有 **UB** 能判矛盾;**LB** 只能推出"必须有隐藏首都"。

## 3. 外部模型评审发现的问题(全部已修)

用 OpenRouter,`"reasoning": {"effort": "none"}`(仓库 README 的提示:这样模型才给最终结论而不是烧光预算的推理轨迹):

- `deepseek/deepseek-v4.1-flash` → 24 KB 评审,60 条发现
- `z-ai/glm-5.3-flash` → 见 §5

### DeepSeek 判 FATAL / MAJOR 的三条(全部成立,已修)

| # | 位置 | 问题 | 修法 |
|---|---|---|---|
| **FATAL** | `tools.grow_states` | **`_adjacent` 连通剪枝会漏掉合法州**。原来的"按索引递增选轨道"组合枚举与连通剪枝不相容:一个低索引轨道可能只有在高索引轨道加入之后才相邻,于是永远选不到。DeepSeek 给了一个具体的反例 | 改成**连通并集枚举**:任一顺序加入相邻轨道,按结果集合去重。**修完后候选数暴涨:12 州 23 → 189,16 州 241 → 3896 —— 证明旧版确实漏掉了 8 倍的合法州** |
| **FATAL** | `tools.symmetry_instances` | **漏了半整数中心的旋转**。`rot180` 只枚举了偶数的 2a/2b(中心在格点),漏掉半格点中心;`rot90/270` 只枚举格点中心,而半格点中心的 4 重旋转同样把格点映成格点 | `rot180` 的 2a/2b 取遍所有整数;`rot90/270` 枚举 `(u,v)` 同奇偶的组合 |
| **MAJOR** | `tools.tight_neighbour_ok` | **对 d=0 的格用了 L1**。d=0 意味着该格**就是首都**,L1("每个 d>0 的格有一个更便宜的邻居")根本不适用 ⇒ 会误杀含已发布首都的合法州 | 开头加 `if v == 0: return None` |

DeepSeek 其余 57 条大多被判为 **"No bug"**(它逐条验算了我用的引理,包括 `|d(x)−d(y)| ≤ k·dist_S`、`min(k,s_y) ∈ [1,k]`、
LB/UB 的方向)。它对 `kernel.py` 的两条 `refD1/refD2` 与 `rot90/270` 提出质疑——**这两条是误报**:
我推导过 `k1 = r0 − c0` 是被逼出来的(σ 保持包围盒 ⇒ `c0+k = r0` ⇒ `k = r0−c0`),
而定向差分测试(3000 个对角对称形状)与仓库 `rules.py` 零分歧。

## 4. 这一轮拿到的**新硬结论**

工具不只是"把已有结论跑一遍",它证伪了我自己的一条推断,并给出两条新的严格约束:

**(a) 我上一轮文档里"12 州核心 5 格(含 `(8,10)`)"被自己的工具证伪。**
加上连通剪枝修复后重扫,12 州锚点 `[(6,10),(7,10),(8,10)]` 的合法候选是 **189 个**(不是 23 个),
而且全部 189 个都无法与任何 8 州候选组成自洽的角 ⇒ **`(8,10)` 属于 12 州这个读法站不住**。
⇒ 上一轮文档 §3 里"12 州核心 5 格 + 三条臂"的结论要降级为**假设**,不能当结论用。

**(b) 新约束:16 州不可能含 `(10,6)` 或 `(10,7)`。**
`(10,8)`、`(10,9)` 同在 16 州 ⇒ `(10,8)→(10,9)` 一步 16,而 `d(10,8)=77=16+61` 正好卡死。
若 16 州还含 `(10,7)`、`(10,6)`,则 `(10,8)→(10,7)→(10,6)→(10,5)` 三步共 48 < 77 ⇒ `d(10,8) ≤ 48` ⇒ 矛盾。
⇒ 16 州里第 10 行只有 `(10,8)`、`(10,9)`(以及可能的 `(10,10)`)。

**(c) 8 州锚点 `[(6,9),(6,10)]` 直接归零**:两个格若同在 8 州,则 `d(6,9) ≤ 8 + d(6,10) ≤ 9` 正好卡死,
但 UB 检查判它矛盾 ⇒ **`(6,9)` 与 `(6,10)` 不在同一州**,这与 D2 的紧边读法一致。

## 4.5 ★ 联合枚举的**两两诊断**结果(本轮最有价值的一条)

三维联合枚举(12 州 × 8 州 × 16 州)在所有测试过的锚点假设下都是 **0 幸存**。
于是改成**两两配对**测试(便宜得多),定位是哪一对冲突:

| 配对 | 幸存数 | 读法 |
|---|---|---|
| (12州, 8州),三种锚点组合 | **0** | ✗ **冲突在这里** |
| (12州, 16州) | **154,507** | ✓ 兼容,几乎不约束 |

**⇒ 破的是 8 州那个假设,不是 12 州与 16 州的关系。**

**杀手的编号是 `(8,8)=45`。** 统计每一对被反驳的原因,几乎全部是:

```
(8,8)  'upper bound 41 < published 45'   ← 1934 次
(8,8)  'upper bound 36 < published 45'   ←  940 次
(8,8)  'upper bound 40 < published 45'   ←  719 次
(10,9) 'upper bound 53 < published 61'   ←  387 次
```

也就是说:**只要在 `(8,8)` 周围放了 12 州或 8 州,`(8,8)` 就会有一条通往已揭示首都的便宜路线,
其代价严格小于 45,与已发布的 45 冲突。**

⇒ **(8,8) 必须属于一个"中型"州,而且这个州不能和 12 州 / 8 州挨得太近。**
从 45 的分解看,候选是:
`45 = 5×9`(9 州,5 步,终点是自己的首都,9 是奇数 ✓)、`45 = 3×15`(15 州)、`45 = 4×11 + 1`(11 州 + 1 步跨出)、
`45 = 44 + 1`(44 州)。**"(8,8) 属于 9/11/15 州"是一个新的、有力得多读法**,比"12 州或 16 州"更贴合 45 这个数。

⇒ 顺带被证伪的还有:上一轮的"读法 A(12 州 = 12+1,出口在 (6,10))"。
若出口真的在 `(6,10)`,州内任一格 x 的 d = 12·dist(x,(6,10)) + 1;`(8,8)` 落在 12 州里就必须是 ≥4 步 ⇒ d ≥ 49 > 45。
**⇒ `(8,8)` 不在 12 州,且 12 州的出口不是 `(6,10)`。**

**下一步(已经排好队):** 把 `(8,8)` 当成一个中型州的锚点重新枚举(9 / 11 / 15 / 22 / 44 州),
和 12 州、16 州一起做三两配对;`45` 与 `51` 的守恒律(45 州 + 50 州 + 37 > 121)会继续压掉一部分。

## 4.6 ★★★ 第一个具体形状出来了:`(8,8)` 那个州是一个 **Γ 形**

执行了上面排队的下一步(`tools/lr11/triple.py`):以 `(8,8)` 为锚,枚举中型州,
再和 (8州,16州) 组合做三重检查。

| `(8,8)` 州面积 | 通过锥形过滤的候选 | 三重组合幸存数 |
|---|---|---|
| 4 | 25 | 0 |
| 6 | 71 | 0 |
| **8** | 73 | **561** |
| 9 | 25 | 0 |
| **10** | 134 | **5,175** |
| **11** | 28 | **546** |
| 12 | 1,175 | (组合爆炸,未跑完) |

**尺寸 8 那一档:所有 561 个幸存组合共用**同一个州**(唯一!)**:

```
M8 = {(6,3), (6,4), (6,5), (7,5), (7,6), (8,6), (8,7), (8,8)}      对称: rot180@(7.0,5.5)
```

**尺寸 10 / 11 那一档的候选是同一个形状加长一格** —— 一根第 6 列的竖脊,底下伸出一个右脚 `(8,7),(8,8)`:

```
M10 = {(3,4),(3,5),(3,6),(4,6),(5,6),(6,6),(7,6),(8,6),(8,7),(8,8)}      对称: rot180@(5.5,6.0)
M11 = {(2,4),(2,5),(2,6),(3,6),(4,6),(5,6),(6,6),(7,6),(8,6),(8,7),(8,8)}  对称: rot180@(5.0,6.0)
```

⇒ **(8,8) 所在州是一个 Γ 形(竖脊 + 底脚),面积 8 / 10 / 11 三选一。**

**11 那一档自带首都 `(5,6)`** —— 它是 rot180 的不动点(奇面积州必有首都),
而 **`45 = 4×11 + 1`** 正好与"11 州里走 4 步 + 一次代价 1 的跨出"对上;
`8` 那一档则是偶面积州(无首都),`45` 得由 8 州之外的出口解释。
⇒ **11 这一档目前最自洽**,但工具没有排除 8 档和 10 档。

**这同时否定了上一轮的"12 州"读法**:12 州(锚 `(6,10)`+`(7,10)`)与 8 州**零组合**,
而 (8州,16州) 有 42,346 个组合、(12州,16州) 十几万个 ⇒
**真正的结构是「Γ 形的 (8,8) 州 + 8 州 + 16 州」,而不是「12 州 + 8 州 + 16 州」。**

**8 州还有 33 个不同候选**(最常见的是 `refV@9.0` 的
`{(3,8),(3,9),(3,10),(4,8),(4,9),(4,10),(5,9),(6,9)}`),
⇒ **下一步是把 8 州也钉死**:给 Γ 州定面积之后,重新做 (Γ, 8州, 16州) 三重枚举,
或者用 `(3,8)=6` / `(4,8)=4` 这两个已发布数去砍 8 州。

## 6. 怎么用

```bash

```
